# 記録照合フェーズ — 5端末デモ

GitHub Pages（静的ホスティング）＋ Firebase Realtime Database で、**スマホ5台**で同時に遊べるデモです。

---

## 1. Firebase の設定（10分・1回だけ）

GitHub Pages はサーバーを持てないため、5台の同期に外部サービスを使います。

1. https://console.firebase.google.com/ で**プロジェクトを作成**（Googleアナリティクスは不要）
2. 左メニュー **構築 → Realtime Database → データベースを作成**
   - ロケーションはどこでもOK
   - **「テストモードで開始」** を選ぶ
3. **プロジェクトの設定（歯車）→ 全般 → 下部「マイアプリ」→ ウェブアプリ（`</>`）を追加**
4. 表示された `firebaseConfig` を **`firebase-config.js`** に貼り付ける
5. `databaseURL` が含まれているか確認。無ければ Realtime Database 画面の
   `https://xxxx.firebaseio.com` を手で足す

### データベースのルール

Realtime Database の **「ルール」タブ**に貼って公開：

```json
{
  "rules": {
    "rooms": {
      "$room": { ".read": true, ".write": true }
    }
  }
}
```

> **誰でも読み書きできる状態です。** デモ以外では使わないこと。
> デモが終わったら Firebase プロジェクトを削除するか、ルールを `false` に戻してください。

---

## 2. GitHub Pages で公開

1. GitHub で**新しいリポジトリ**を作る（Public）
2. この `demo/` フォルダの中身（`index.html` / `cards.js` / `firebase-config.js` / `README.md`）をアップロード
3. リポジトリの **Settings → Pages**
   - Source: **Deploy from a branch**
   - Branch: **main** / **/(root)**
4. 数十秒待つと `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される

> リポジトリを Public にすると `firebase-config.js` も公開されます。
> Firebase のウェブ用APIキーは公開前提の値なので問題ありませんが、
> **ルールを緩めたままのプロジェクトを長期間放置しない**でください。

---

## 3. 遊び方

1. 5人が同じURLをスマホで開く
2. **同じ部屋コード**（英数4文字など、何でもよい）を全員が入力して「この部屋に入る／作る」
3. **席（PC1〜PC5）を選ぶ**。先着順。**最初に席に着いた人がホスト**になります
4. ホストの端末で **「開始」**

---

## 1台だけで確認する

5台そろわないときの方法が2つあります。

### A. ソロ確認モード（1画面で全席を動かす）

URLの末尾に **`?solo=1`** を付けて開くだけ。

```
https://<ユーザー名>.github.io/<リポジトリ名>/?solo=1
```

- 席選択が飛ばされ、**5席すべてを1人で操作**できます
- 画面上部に **PC1〜PC5の切り替えバー**が出ます
- **引きターンは手番の席へ自動で切り替わります**（手動でも切替可）
- 「開始」「交渉終了」などのホスト操作は常に使えます

ルールの流れ・尺・詰まりを1人で確認したいときはこれが一番速いです。
**秘匿は効きません**（全員の手札が見られます）。

### B. 5タブ／5ウィンドウで開く（本番に近い）

**同じPCで複数のタブを開く**と、それぞれ別プレイヤーとして参加できます。
端末IDをタブごとに持つようにしてあるため、5タブ＝5人分として動きます。

1. 通常のURL（`?solo=1` なし）を**5つのタブ**で開く
2. 全部に**同じ部屋コード**を入れる
3. タブごとに**別々の席**を選ぶ

ウィンドウを並べれば、同期の様子が目で見えます。
**タブを閉じると席の権利を失う**ので、閉じずに並べたままにしてください。

---

### 1ラウンドの流れ

| | フェーズ | 時間 | 内容 |
|---|---|---|---|
| 1 | 抽選 | 自動 | 全員のダイスが振られ、行動順が決まる |
| 2 | **交渉ターン** | **60秒** | 全員同時。口頭で交渉し、画面で交換を成立させる |
| 3 | **引きターン** | 1人20秒 | 出目順。相手を指名 → 1枚引く → 1枚渡す |

**16ラウンドで終了。** 山札が尽きた後も、手札のペアを作り続けます。

### 操作

| したいこと | 操作 |
|---|---|
| ペアを作る | 手札から**2枚タップ** → 下部「照合する」 |
| カードを交換する（交渉ターン） | 出すカードを**1枚タップ** → 「交換を申請」→ 相手番号を入力 |
| 交換を承認する | 自分の手札を**1枚タップ**してから「承認」 |
| 情報データを渡す | 「情報を渡す」→ 情報番号と相手番号を入力 |
| 効果カードを使う | 手札から**1枚タップ** → 「効果カードを使う」 |
| 相手を指名する（引きターン） | 上の枠の相手を**タップ** |

### 覚えておくこと

- **金色の枠＝自分の記憶記録。** 本番では「光る」演出になります。他人には見えません
- **事件記録（灰色）は全員に内容が見えます。** 記憶記録と効果カードは伏せ札で、位置だけ見えます
- **20秒で操作しないと、指名先・引く札・渡す札がすべてランダムで自動処理されます。**
  自分の記憶記録を手放してしまうこともあります（UZUには「それが誰の記憶か」が見えていないため）
- **口約束を守る義務はありません**

## 4. デモ版で省略していること

| | デモ | 本番 |
|---|---|---|
| UI | 汎用のダークUI | ドット絵 → 転換演出でリアルへ変化 |
| 魂の記憶 | テキスト通知＋バイブ | **音と映像**で当事者へ配信。5台同時に一瞬ノイズ |
| 効果カード | 相互置換・開示制御は**手動処理**（宣言のみ） | すべて自動 |
| 対象指定 | 一部は番号を手入力 | タップで選択 |
| カードID | 層とID範囲が対応している | 完全ランダム化（層が推測されないように） |
| 認証・不正防止 | なし（信頼ベース） | サーバー権威 |

## 5. 測ること

テスト中、以下をメモしてください。

- 1ラウンドの実所要時間（想定 2分45秒）
- 交渉60秒で成立した交換の件数
- 引きターン1人20秒は足りたか
- **16ラウンドで成立したペア数**（目標 25）
- 山札が尽きたタイミングと、その後の膠着時間
- 時間切れの自動処理が起きた回数
- **ペア照合の難易度**（簡単すぎ／難しすぎ）
- 最後にジョーカー（X-01）が1枚だけ残ったか

---

## 6. リセット

部屋の状態は Firebase に残ります。同じ部屋コードで最初からやり直したい場合は、
Firebase コンソールの Realtime Database で `rooms/<コード>` を削除してください。
別のコードで入り直せば新しい部屋として始まります。
